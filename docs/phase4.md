# Phase 4 — 폴리시 & 튜닝

Phase 1~3가 기능적으로 동작하는 상태에서 시작. Phase 4는 **대량 인원 대응, 시각적 가독성, 인사이트 전달**에 집중한다.

## 항목 (우선순위 순)

1. 블록 압축 표시 + FP 비율 누적 막대
2. 보간 시정수 K값 실측 튜닝 (1x~600x 자연스러움)
3. 대표 비교 지표 헤드라인 강조
4. 시나리오 프리셋 버튼
5. 색상/여백/타이포 다듬기
6. 폐장 시 빨간 배너 + 실패자 시각화
7. Notion embed 동작 확인
8. 단일 `index.html` 인라인 빌드

## 1. 블록 압축 (요구사항: plan.md 추가사항)

**트리거 조건**:
- 한 줄 점 개수 > 임계 (예: 250개) **또는**
- 점 간격 < 4px 가 되도록 강제됨

**블록 사양**:
- 블록 크기 고정: 가로 20px × 세로 14px
- 한 블록당 인원 N_block: 줄 길이에 비례 동적 (50/100/200/500…)
- 블록 간 간격 2px, 줄 경로 위에 정렬
- 블록 위에 작은 숫자 라벨 (예: `100`)

**FP/일반 비율 시각화 (핵심 요구)**:
한 블록 내 FP 비율 p:
1. `cells = ceil(p / 0.05)` — 5% 단위 올림 (0% 초과면 최소 1px)
2. 블록의 좌측 `cells`px 세로 영역을 금색 채움
3. 나머지 우측을 파랑 채움
4. 좌·우 영역 경계는 1px 명도 차이로 또렷하게

예시 (가로 20px 블록):
- p = 0%: 전체 파랑
- p = 1%: 좌 1px 금색 + 우 19px 파랑
- p = 35%: 좌 7px 금색 + 우 13px 파랑
- p = 100%: 전체 금색

**구현**:
- Renderer가 "블록 모드" 활성화 시 점 그리기 대신 사각형 그리기
- 한 블록의 FP 인원수는 큐에서 해당 구간의 hasFastPass 카운트
- 우측 패스트트랙줄은 정의상 100% → 항상 전체 금색

블록 ↔ 점 모드 전환은 한 큐가 임계를 넘는 순간 즉시. 깜빡임 방지를 위해 +/- 10% 히스테리시스.

## 2. 보간 시정수 튜닝

`τ = clamp(0.15, 0.6, K / sqrt(simSpeed))` 의 K값을 실측.

**튜닝 방법**:
- 한산~혼잡 두 시나리오 × 1x/10x/60x/300x/600x 5단계 = 10가지 조합
- 각 배속에서 30초 관찰 → "점이 끊겨 보이지 않으면서 사이클 발차 시 흡수가 너무 늦지 않은" K 선택
- 시작 추정: K=4.0
- 조정 후보: 2.5, 3.0, 3.5, 4.0, 5.0, 6.0
- 채택값을 코드에 상수로 박고 주석으로 근거 기록

**탑승 슬라이드 별도 시정수**:
- ride 흡수는 사이클 간격(real time)의 절반 이내에 완료
- `τ_board = max(0.1, cycleSec / simSpeed * 0.3)`

## 3. 헤드라인 비교 지표

통계 표 위에 큰 글씨:
```
┌──────────────────────────────────────────────────────────────┐
│  일반줄 평균 대기:  32.0분  →  44.3분   (+12.3분)            │
│  패스 소지자:               53.5분  →  25.0분  (−28.5분)     │
│  탑승 실패:        좌 0명 / 우 0명                            │
└──────────────────────────────────────────────────────────────┘
```

- "+12.3분"은 빨간색, "−28.5분"은 녹색
- 실패자 0보다 크면 빨간 배경 강조

## 4. 시나리오 프리셋

컨트롤 패널 상단:
```
프리셋: [평일 한산] [주말 보통] [성수기 혼잡] [패스 과다]
```

각 프리셋 = 파라미터 세트 정의. 누르면 슬라이더 값 일괄 변경 + Apply & Restart 자동 실행.

기본 4종:
- **평일 한산**: visitors 2500, FP 200, peakWait 30분
- **주말 보통**: visitors 6000, FP 800, peakWait 90분 (기본값과 유사)
- **성수기 혼잡**: visitors 10000, FP 1500, peakWait 180분
- **패스 과다**: visitors 6000, FP 2500, fpPercent 60, peakWait 120분 (일반줄 폭주를 보여주는 시범)

## 5. 색상·여백·타이포

- 색상 토큰을 CSS variable로 정리 (`--c-fp`, `--c-reg`, `--c-bg`, `--c-warn`)
- 폰트: system-ui, 한글 가독 우선
- 컨트롤 패널 너비 280px 고정
- 패널 간 구분선 미세 그림자
- 다크 모드 미지원(데스크톱 우선, 단순화)

## 6. 폐장 처리 시각

- 폐장 시각 도달 → ride 영역에 빨간 테두리 + "폐장" 텍스트
- 남은 점/블록은 그대로 정지 (실패자 시각화)
- 헤드라인 지표의 "탑승 실패" 강조 활성화
- 통계 표 헤더에 "최종 결과" 배지

## 7. Notion Embed 검증

- iframe 환경에서:
  - 외부 fetch 0, 외부 리소스 링크 0
  - 자동 재생 비활성, 사용자 명시적 Play 필요
  - 작은 iframe 크기(예: 800×600)에서 컨트롤 접힘 처리
- 검증: Notion 페이지에 `/embed` 후 작동 확인 스크린샷

## 8. 인라인 빌드

`src/*.js`와 `index.html`을 단일 파일로 결합:
- 빌드 스크립트(`build.mjs` 또는 PowerShell): `<script src="src/x.js">` 라인을 해당 파일 내용으로 치환
- CSS도 인라인
- 결과: `dist/fasttrack.html` (또는 그냥 루트 `fasttrack.html`)
- 외부 도구 없이 표준 Node/PowerShell만으로 동작

## 검증

1. 큐 1000명 → 블록 압축 + FP 비율이 한눈에 보임 (p=25% 블록과 p=75% 블록의 막대 차이가 또렷)
2. 600x 배속에서 점/블록이 끊기지 않고 흐름
3. 프리셋 "패스 과다" → 헤드라인이 빨간 +Δ로 인사이트 강조
4. 폐장 시각 도달 → 빨간 배너 + 실패자 시각화
5. Notion에 embed → 컨트롤 모두 동작
6. 단일 `fasttrack.html`을 더블클릭 → 모든 기능 동일하게 동작
