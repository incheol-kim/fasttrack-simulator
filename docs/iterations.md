## 1. 도착 모델 (arrival.js) — 핵심 모델 수정

### 1.1 피크/비피크 인버전 버그 발견
사용자가 과부하 시나리오(입장 30,000명, 혼잡도 2.50)에서 우-패스 통계가 **피크 29.2분 < 비피크 50.6분**으로 비직관적인 결과를 발견.

**원인 분석**: 기존 모델은 `peakMaxWaitMin`로부터 λ_peak를 도출하고 남은 인원을 λ_off로 채웠다. 그 결과:
- λ_peak = 0.417/초 (피크)
- λ_off = 0.833/초 (비피크) ← 피크보다 2배 높음!

명목상 "피크"가 실제로는 한산한 시간이 되어버리는 **인버전** 발생.

### 1.2 새 모델 — 균등 분포 후 α boost / β cut (총합 보존)
사용자 제안에 따라 모델 재설계:
- λ_avg = dailyVisitors / 영업초
- α = peakMaxWaitMin · 60 / peakSec (피크 강도)
- β = α · peakSec / offPeakSec (총합 보존)
- λ_peak = λ_avg · (1 + α)
- λ_off = λ_avg · (1 − β)

**보장**: 항상 λ_peak > λ_off, 1일 총량은 dailyVisitors와 일치.
**클램프**: β > 0.95이면 α 하향 조정 + flagged 표시.

### 1.3 peakMaxWaitMin의 의미 재해석
사용자 질문 "정확한 값인가 경향성인가?"에 따라 파라미터의 본질이 **강도 계수**임이 드러남:
- 라벨 변경: `피크 최대 대기 (분)` → `피크 강도 (분)`
- 툴팁 보강: "혼잡도 ≈ 1.0일 때만 실제 피크 최대 대기 ≈ 이 값에 근사. 그 외엔 어긋남."

## 2. 통계 분류 — UX 개선

### 2.1 라이브 업데이트 시점 혼동
사용자가 13:42 wall-clock에서 피크 통계 셀이 비어 있는 현상을 보고. 원인은 분류 기준이 **줄에 합류한 시각**인데 큐가 길어 피크에 합류한 사람이 아직 미탑승 상태이기 때문.

### 2.2 분류 기준 유지 + UX 보강 결정
"도착 시각 기준"의 의미적 정합성을 유지하되 시각적 혼란 해소:
- **Simulator에 버킷별 카운터 추가**: `arrived`, `waiting` (peak/offpeak × regular/fastpass)
- **셀 형식 변경**: `2960명 · 64.4±36.3` → `936/1476명 · 대기 540 · 64.4±36.3`
- **헤더 라벨 명확화**: `피크 도착` → `피크타임에 줄에 합류`
- **안내문 추가**: 분류 기준이 줄 합류 시각이고 "대기" 카운트가 큐 누적의 시각화

### 2.3 "도착" 표현 정리
모호함 해소 — 사용자 노출 텍스트에서 "도착" 단어 전부 제거:
- 셀 형식: "탑승완료/총도착" → `탑승완료/총인원`
- 패널 카운터: `도착` → `줄 합류`

## 3. 파라미터 조정

| 파라미터 | 원래 | 변경 | 사유 |
|---|---|---|---|
| `dailyFastPassCount` 상한 | 5,000 | **50,000** | 사용자 요청. 입장객수와 동일 범위 |

| `peakMaxWaitMin` 라벨 | "피크 최대 대기 (분)" | **"피크 강도 (분)"** | 경향성·강도 계수임을 명확화 |
| 파라미터 정렬 | (default) | **FP 비율을 1회 탑승인원 바로 아래로** | 사용자 요청 — 의존 관계 시각화 |

## 4. UI 컨트롤 변경

### 4.1 시간 컨트롤 슬라이더화
사용자 보고: 피크 시작/종료를 설정할 수 없고 "오전/오후" 부분에 의미 없는 에디트창이 보임.
**원인**: 네이티브 `<input type="time">`이 컨트롤 폭(76px)에 잘려 한국어 로케일의 오전/오후 dropdown만 보이고 HH:MM 편집 영역이 잘림.
**해결**: 4개 시간 컨트롤(개장·폐장·피크 시작·피크 종료) 모두 **range 슬라이더 + HH:MM 라벨**로 통일.

### 4.2 컨트롤 패널 헤더
- 메인 타이틀 추가: `놀이공원 패스트트랙 시뮬레이터`
- `파라미터`는 소제목으로 격하
- 컨트롤 상하 간격 축소 (margin-bottom 12px → 6px 등) → 한 화면에 더 잘 들어옴

### 4.3 한국어 타이틀 줄바꿈
"놀이공원 패스트트랙 시뮬레이터"가 좁은 패널에서 "시뮬레" 뒤에 임의로 줄바꿈됐던 문제 → `<br>`로 명시적 분할: "놀이공원 패스트트랙" / "시뮬레이터".

## 5. 새 기능 — 원 plan에 없던 추가

### 5.1 툴팁 시스템 (`src/tooltip.js`)
모든 라벨에 ⓘ 아이콘 + 마우스오버 말풍선. 처음엔 6개(통계 라벨)만 추가 → 사용자 요청으로 확장:
- 10개 파라미터
- 배속 그룹 + 5개 배속 버튼 (각각 동적 툴팁)
- 혼잡도
- 6개 통계 라벨 (좌-일반/우-일반/우-패스 + 일반줄 평균/패스 대기/탑승 실패)
- 3개 통계 표 헤더 (전체/피크/비피크)

총 **21개 ⓘ 아이콘**, `position: fixed` 기반 자동 위치 보정.

**버그**: 큰따옴표 `"` 포함된 툴팁이 HTML 속성을 조기 종료 → 한국식 따옴표 「」로 변경.

**동적 툴팁**: 배속 버튼은 영업 시간(`closeTime - openTime`)에 따라 "{X}시간 운영을 약 Y에 관찰" 문구가 실시간 계산되어 표시.

### 5.2 다크/라이트 테마 토글 (`src/theme.js`)
- 30+개 CSS 변수 (`--bg`, `--canvas-bg`, `--badge-*` 등)
- `[data-theme="light"]` 오버라이드
- Canvas는 `getComputedStyle`로 CSS 변수 읽어 동적 색상 갱신
- `localStorage`에 선택 영속화

### 5.3 도움말 모달 (`?` 버튼)
프로그램 전체 설명용 팝업. 좌상단 타이틀 옆 `?` 버튼 → 화면 중앙 다크 배경 모달:
- 이 프로그램이 답하는 질문 / 핵심 동작 / 화면 구성 / 핵심 인사이트 / 사용 팁
- 닫기: ×, 배경 클릭, Esc 키
- `position: fixed` 안전 위치 + 스크롤 가능

### 5.4 i18n — 한·영·일 (`src/i18n.js`)
200+ 키 사전, 언어 토글 버튼(`한`/`EN`/`日`), `localStorage` 영속화. 모든 노출 텍스트 번역:
- 파라미터 라벨·툴팁
- 통계 라벨·헤더·셀 형식
- 캔버스 라벨(`refreshLabels` 캐시)
- 헬프 모달 본문 (`help.html` per language)
- `validateParams` 결과 (i18n 키 반환)
- 동적 시간 포맷 ("약 N시간 M분" / "about Xh Ymin" / "約 Xh M分")

**번역 결정**:
- 영어: `theme park` → `amusement park` (의미적 정확성, 사용자 결정)
- 일본어: `テーマパーク` 유지 (관용 표현)
- 한국어 타이틀: `<br>` 줄바꿈 강제

언어 변경 시 `FT.ui.rebuildAll()`로 전체 UI 재렌더, 이벤트 위임 패턴으로 listener 손실 없음.

### 5.5 시나리오 프리셋
4가지 미리 정의된 시나리오 버튼 (한산/보통/혼잡/패스 과다) — 한 번 클릭으로 파라미터 적용 + 재시작.

### 5.6 블록 압축 시각화 (Phase 4 추가사항 구현)
원 plan에 명시는 있었지만 실구현 디테일:
- 큐 > 250명이면 자동 전환 (히스테리시스 200/250)
- 각 블록 = N명 (50/100/200/...)
- **블록 왼쪽 금색 폭이 그 구간의 FP 비율** (5% 단위 올림, 1% 이상이면 최소 1px)

### 5.7 안전 입장객수 미리보기
입장객수 입력란 아래에 `안전 권장: ≤ N명` 라이브 표시 (= `dailyTotalSeats × 0.85`).
