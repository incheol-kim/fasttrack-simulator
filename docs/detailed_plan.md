# Fasttrack Simulator — 상세 계획

`plan.md`의 요구사항을 구현 가능한 단위로 분해한 설계 문서. 단일 `index.html` 산출물이 목표.

---

## 1. 결과물 개요

- `index.html` 하나로 동작 (외부 CDN 의존성 0, 자체 JS/CSS 포함)
- Canvas 2D 기반 시각화 + 좌측 컨트롤 패널 + 하단 통계 패널
- 화면 좌우 2분할: 좌(패스트트랙 없음) / 우(패스트트랙 있음)
- 좌·우는 **동일한 손님 도착 이벤트 스트림**을 공유. 차이는 "패스트트랙권 소지자가 어느 줄에 서느냐"뿐
- Notion embed로도 동작해야 하므로 단일 파일·iframe-safe (외부 fetch/네트워크 호출 없음)
- 데스크톱 가로 화면 우선 (모바일 대응 보류)

## 2. 파라미터 사양

모두 좌측 컨트롤 패널에서 실시간 변경 가능. 파라미터 변경 → "Apply & Restart" 적용. 단, **혼잡도와 안전입장객수 표시는 즉시 갱신**.

| ID | 이름 | 기본값 | 범위 | 단위 |
|---|---|---|---|---|
| `openTime` | 개장시각 | 10:00 | 06:00–12:00 | HH:MM |
| `closeTime` | 폐장시각 | 22:00 | 18:00–24:00 | HH:MM |
| `dailyVisitors` | 1일 입장객수 | 6000 | 100–50000 | 명 |
| `dailyFastPassCount` | 1일 패스트트랙권 판매장수 (항상 매진) | 800 | 0–min(dailyVisitors, 5000) | 장 |
| `capacityPerCycle` | 1회 탑승인원 | 24 | 4–60 | 명 |
| `cycleDurationSec` | 1회 가동시간 | 180 (3분) | 30–900 | 초 |
| `fastPassPercentPerCycle` | 1회당 패스트트랙 허용 비율 | 33 (%) | 0–100 | % |
| `peakStart` | 피크타임 시작 | 12:00 | open–close | HH:MM |
| `peakEnd` | 피크타임 종료 | 16:00 | start–close | HH:MM |
| `peakMaxWaitMin` | 피크타임 일반줄 대략 최대 대기 | 120 (2시간) | 10–300 | 분 |
| `simSpeed` | 시뮬레이션 배속 | 60x | 1x–600x | (재생 컨트롤) |

**파생값**

- `cyclesPerHour` = 3600 / cycleDurationSec
- `dailyCycles` = (closeTime − openTime) × cyclesPerHour
- `dailyTotalSeats` = dailyCycles × capacityPerCycle
- `fastPassSlotsPerCycle` = floor(capacityPerCycle × fastPassPercentPerCycle / 100)
- `safeDailyVisitors` (입장객수 입력란 옆에 라이브 표시): 아래 §3.2 참조

**패스트트랙권은 항상 매진**: dailyFastPassCount는 그날 실제로 사용되는 패스 수와 동일. 도착 흐름 안에 균등 stratified 배치 (§4.2).

## 3. 혼잡도 & 안전 입장객수 산출

### 3.1 혼잡도 (Congestion Index)

```
congestion = dailyVisitors / dailyTotalSeats
```

표시 단계:
- `< 0.6` → 한산 (녹색)
- `0.6 – 0.9` → 보통 (노랑)
- `0.9 – 1.05` → 혼잡 (주황)
- `> 1.05` → 매우 혼잡 / 폐장 시 탑승 실패자 발생 가능 (빨강)

파라미터 변경 즉시(시뮬 재시작 없이) 다시 계산해 컨트롤 패널에 뱃지로 표시.

### 3.2 안전 입장객수 (`safeDailyVisitors`)

"파라미터 입력시, 다른 파라미터들로부터 계산하여 대략 안전하게 모두 탑승가능한 일일 입장객수를 일일입장객수 입력란 근처에 미리 보여주도록" 요구사항.

```
safeDailyVisitors = floor(dailyTotalSeats × 0.85)
```

- 0.85 버퍼는 피크 집중에 따른 사이클 손실(피크 후반 빈자리 발생) + 패스트트랙 잔여 미사용 슬롯 흡수 여유분
- 입장객수 입력란 아래에 회색 작은 글씨로 `"안전 권장: ≤ 5,202명"` 형태로 표시
- 사용자가 그 이상으로 설정하면 탑승 실패가 발생할 수 있다는 의미가 시각적으로 전달됨 (혼잡도 뱃지 색과 함께)

## 4. 시뮬레이션 모델

### 4.1 시간 진행

- 시뮬레이션 시계 `simTime` (초 단위, 개장 시각 = 0)
- 메인 루프: `requestAnimationFrame`에서 `dt_real`을 측정 → `dt_sim = dt_real * simSpeed`
- 한 프레임 안에서 작은 step(예: 1 sim-second)으로 잘라 처리. 배속이 높아도 도착/탑승 이벤트가 정확한 시각에 발화

### 4.2 손님 도착 모델 (양쪽 공유)

총 도착 수는 정확히 `dailyVisitors`. 시간 분포는 피크/오프피크 강도로 결정.

**Step 1 — 시간대별 평균 도착률 λ(t) 결정**

- 서비스율: `μ = capacityPerCycle / cycleDurationSec` (명/초)
- 피크 강도 역산 (Little's Law 기반):
  ```
  λ_peak (명/초) = μ × (1 + peakMaxWaitMin / (60 × peakDurationHours))
  ```
  (피크 동안 큐가 자라서 피크 종료 즈음 대기시간이 `peakMaxWaitMin`에 근접하도록)
- 오프피크 도착률:
  ```
  λ_off = max(0, (dailyVisitors − λ_peak × peakSeconds) / offPeakSeconds)
  ```
- λ_off가 음수가 되는 경우(피크 강도가 dailyVisitors에 비해 너무 큼) → 컨트롤 패널에서 경고 + λ_peak를 자동으로 낮춰 dailyVisitors와 일관성 유지

**Step 2 — 도착 시각 N개 샘플링**

- N = dailyVisitors
- 누적 분포 F(t) = ∫λ(s)ds / dailyVisitors 를 계산해두고, `Uniform(0,1) → F⁻¹` 으로 N개 샘플 추출 (역CDF 샘플링)
- 균등 도착보다 자연스러운 무작위성을 위해 작은 jitter 추가 (±30초)
- 결과: 정렬된 도착 시각 배열 `arrivalTimes[N]`

**Step 3 — 패스트트랙권 소지자 stratified 배정**

- 요구: "패스트트랙권을 가진 사람도 전체적으로 균일하게 분포되도록", "항상 매진"
- N명을 도착 순서대로 나열 → `dailyFastPassCount`명을 균등 간격으로 선택 (stratified): 인덱스 `floor((k + 0.5) × N / dailyFastPassCount)`, k = 0…dailyFastPassCount−1
- 선택된 사람의 `hasFastPass = true`

**Step 4 — 좌·우 동기 주입**

- 동일 personId, arrivalTime, hasFastPass를 좌·우 시뮬레이터에 동시 push
- 좌측: hasFastPass 무시 → 항상 일반줄
- 우측: hasFastPass=true → 패스트트랙줄, false → 일반줄

### 4.3 탑승 사이클 로직

매 `cycleDurationSec`마다 발차. 한 사이클:

**좌측 (패스트트랙 없음)**
- 일반줄 앞쪽 `capacityPerCycle`명 탑승

**우측 (패스트트랙 있음)**
1. 패스트트랙줄에서 `min(fastPassSlotsPerCycle, FP큐 길이)`명 탑승
2. 남은 좌석을 일반줄에서 채움
3. 일반줄까지 부족하면 패스트트랙줄에서 추가로 끌어와 채움 (빈틈없이)
4. 한 사이클의 실제 탑승자 수 = min(capacityPerCycle, FP큐 + 일반큐)

### 4.4 폐장 처리 & 탑승 실패

- `simTime ≥ closeTime`이 되면 신규 도착 중단
- 마지막 사이클 발차 후에도 남은 손님 = **탑승 실패자**
- 통계에 별도 집계 (좌·우 각각, FP 소지자/일반 분리)
- 시각화에서 빨간 배너로 "Failed: N명" 표시

### 4.5 Person 객체

```js
{
  id, side,                    // 'L' | 'R'
  hasFastPass,                 // 우측에서만 의미
  arrivalTime,                 // 줄에 도착한 sim time
  boardingTime,                // 탑승 시각 (없으면 null = 탑승 실패)
  waitSec,                     // boardingTime - arrivalTime (실패 시 closeTime - arrivalTime)
  queue: 'regular'|'fastpass',
  posIndex,                    // 줄에서의 논리적 위치 (0이 맨 앞)
  visual: { x, y, vx, vy }     // 시각 좌표(현재) 및 보간 속도. 논리 위치로 lerp.
}
```

### 5.2 사람·줄 그리기 (인원 적을 때)

- 줄은 **뱀(snake) 경로**로 접어서 표시. 길어지면 자동으로 더 많은 굴곡 추가
- 사람 = 작은 원 (반지름 3–5px). 위치는 `posIndex`를 경로 매개변수로 변환
- 색상:
  - 일반 손님: 파랑 (#3a7dff 등)
  - 패스트트랙 소지자: 금색 (#e6b800 등)
  - 탑승 직전(맨 앞 1–2명): 살짝 강조 (테두리 굵게 또는 펄스)
- 탑승: 줄 맨 앞 사람이 ride 영역으로 슬라이드/페이드아웃 → 사이클 카운터 +1

### 5.3 블록 압축 표시 (인원 많을 때)

화면 폭/줄 길이 기준 임계치(예: 한 화면에 200명 초과 또는 점 간격 < 4px)를 넘으면 블록 단위 압축.

**블록 사양**
- 블록 = 한 사각형. 한 블록이 표현하는 인원수 N_block은 동적 (예: 50, 100, 200… 줄 길이에 비례)
- 사각형 크기는 고정 (예: 가로 20px × 세로 14px)
- 블록 안에 **숫자 라벨** ("100명")

**FP/일반 비율 시각화 (plan.md 추가사항)**
- 한 블록 내 패스 비율 p = (블록 내 FP 인원) / N_block
- 표시 방식: **세로 막대 누적** — 가로 폭 20px을 5% 단위로 1px씩 분할 → 패스 비율만큼 좌측을 금색으로 채우고, 나머지를 파랑으로
  - 예: p=35% → 좌측 7px 금색, 우측 13px 파랑
  - 5% 단위 올림(round up)으로 1px 미만 비율도 시각적으로 드러나도록 ("0이 아니면 최소 1px")
- 보조: 블록 테두리 색은 우세한 쪽 색상(가독성 향상)
- 우측 패스트트랙줄에는 정의상 100% 금색이므로 블록도 전체 금색

### 5.4 보간 시간 상수 (배속 600x 대응)

요구: "배속 600x에서도 사람 점이 자연스럽게 보이려면 렌더 보간 시간 상수 조정 필요 → 최적 조정값 찾아서 적용"

**문제**: 600x에서 1 real-sec = 600 sim-sec. 사이클(180 sim-sec)이 0.3 real-sec마다 발차. 사람이 매 프레임 큰 거리를 점프하면 부자연스러움.

**해결 전략**:
- 각 사람의 시각 좌표는 논리 좌표(`targetX, targetY`)를 향해 **지수 감쇠 보간**:
  ```
  x += (targetX - x) * (1 - exp(-dt_real / τ))
  ```
- 시정수 τ는 배속의 함수로 정의:
  ```
  τ = clamp(0.15, 0.6, k / sqrt(simSpeed))
  ```
  - 1x 기준 τ ≈ 0.6s, 600x 기준 τ ≈ 0.15s (하한)
  - `k`는 튜닝 상수, 초기값 4.0 → Phase 4에서 실측으로 미세조정
- 탑승 애니메이션(slide out): 탑승 사이클 간격(real time)의 절반 이내에 완료되도록 별도 시정수

**Phase 4 튜닝 절차**:
1. 배속 1x, 10x, 60x, 300x, 600x에서 각각 줄 진행을 30초씩 녹화/관찰
2. "사람이 뚝뚝 끊겨 보이지 않으면서, 너무 늘어지지도 않는" k값 채택
3. 채택값을 코드에 상수로 박아둠

## 7. 통계 (Stats Panel)

각 손님 `waitSec`을 다음 분할로 집계.

**분할 차원**
- 시간대: 전체 / 피크 / 비피크 (도착시각 기준)
- 줄 종류: 좌측-일반, 우측-일반, 우측-패스
- 탑승 성공 / 탑승 실패 별도

**지표**
- 최소, 최대, 평균, 분산, 표준편차, 표본수 (모두 분 단위)
- 탑승 실패자는 wait 통계와 분리, 카운트만

**표시 방식**
- 표 형태 (3분할 시간대 × 3분할 줄 = 9 셀, 각 셀에 5지표)
- 시뮬 진행 중 라이브 갱신
- 폐장 후 최종 결과 강조

**대표 비교 지표 (큰 글씨)**
- "패스트트랙 도입으로 일반줄 평균 대기 **+Δ분**" — 좌-일반 vs 우-일반
- "패스트트랙 소지자 평균 단축 **−Δ분**" — 좌-일반 vs 우-패스
- "탑승 실패: 좌 N명 / 우 M명" — 둘이 다르면 강조 (보통 동일하지만 우측이 큐 분리로 약간 더 많을 수 있음)

```
└─ <script>
    ├─ Params              파라미터 상태 + 직렬화
    ├─ Derived             cyclesPerHour, dailyTotalSeats, safeDailyVisitors, congestion
    ├─ ArrivalGenerator    λ(t) + 역CDF + stratified FP 배정 + jitter
    ├─ Simulator           좌·우 두 인스턴스, 사이클 처리, 폐장 처리
    ├─ Person              객체 + 위치 보간(시정수 기반)
    ├─ Stats               집계기 (분할별 누적, 실패자 별도)
    ├─ Renderer            Canvas 그리기 (적은 인원=점, 많은 인원=블록 압축 + 비율 막대)
    ├─ UI                  슬라이더 바인딩, 버튼, 상태바, 안전입장객수 표시
    └─ main loop           rAF, dt_real → dt_sim, step → render
```

개발 중에는 `src/*.js`로 쪼개서 작업 가능. 최종 배포 시 단순 concat 스크립트로 `index.html`에 인라인 결합.

## 10. 검증 시나리오 (모델 정합성 확인용)

1. **패스 0장**: 좌·우 통계 정확히 동일 (회귀 테스트성)
2. **혼잡도 ≈ 1.0, 패스 비율 33%**: 우측-일반 평균 대기가 좌측-일반보다 의미있게 증가 (핵심 인사이트)
3. **혼잡도 < 0.6**: 양쪽 모두 짧음, 차이 미미
4. **혼잡도 > 1.05**: 폐장 시 탑승 실패자 발생 + 빨간 배너 표시
5. **패스 슬롯 50%, 패스 판매 적음**: 패스줄이 매번 미달 → 일반줄로 빈 슬롯 회수되어 좌측과 거의 동일한 결과
6. **stratified FP 배정 확인**: 1시간 단위 버킷별 FP 등장 빈도가 도착량에 비례하는지 (분포 균등성)
